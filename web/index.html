Access control on part of a file

Two real readers fetch two real files over HTTP range requests. Every range they ask for is resolved to the column chunks or image tiles it lands in, and checked against the CQL2 policy below before it is fetched. The question this page answers is not whether a policy can be written — it is whether a reader issues ranges a policy can act on.

The read pattern is not the same for the two formats. Parquet keeps its footer at the end, so the first read is a suffix; a GeoTIFF keeps its IFDs at the front, so the first read is a prefix. Both start at 16 KB and double until the metadata fits.

Cross-origin, the host has to opt in three times: Access-Control-Allow-Origin, an OPTIONS answer carrying Access-Control-Allow-Headers: Range (Range is not a safelisted request header, so a ranged GET preflights), and Access-Control-Expose-Headers: Content-Range. Most buckets send none of them, and no amount of code on this page can substitute for any of them.
